# TrackWood

Video-based measurement of floating wood transport in open-channel flume experiments:
detection (RF-DETR or YOLO11), multi-object tracking and virtual-line counting, with
the counting accuracy evaluated against the known number of wood pieces released in
each run.

This repository accompanies a manuscript in preparation for *Measurement*. It is
developed within TÜBİTAK 1001 project 124M033 ("Akımla Taşınan Odunların Sebep Olduğu
Taşkınların Önlenmesinde Geçirgen Mahmuzların Etkilerinin İncelenmesi").

### Physical scale, velocity and flux

The channel is B = 1.2 m wide. The bed-wall junctions give a bed width of 1020–1070 px
across the frame (the camera is slightly off-centre); wood floats at the surface, about
1.5 % wider in the image, so the scale is 1.149 mm/px at L1 and 1.118 mm/px at L2
(relative standard uncertainty 0.9 %, `scripts/calibrate.py`). At L1 the wood surface
velocity is 0.49–0.51 m/s for discharge code 40 and 0.55–0.59 m/s for code 60; RF-DETR
and YOLO11m agree within 0.002 m/s. Mean wood flux reaches about 40 pieces/s, with
1-s peaks of about 50 (`results/physical_summary.csv`).

### Dead-zone model of the original crossing rule

A rule that ignores track centres within ±1 px of the line (width w = 2 px) misses a
crossing whenever one tracker update falls inside that zone. For updates of uniform phase
advancing d px each, P(miss) = min(1, w/d); in physical units P = min(1, w s f / v) for
pixel size s, frame rate f and velocity v. Over 4953 crossings the observed loss is
45.4 % against 45.7 % predicted. In 99.98 % of the crossings, "an update fell in the zone"
and "the original rule missed it" coincide. The observed loss follows the model across
d = 2–40 px (`results/deadzone_model.json`, `figures/fig_deadzone_model.pdf`). A
higher frame rate or a finer resolution therefore increases the loss: a dead band must
be replaced by a last-non-zero-side rule, not tuned.

N is known only at the inlet: pieces held by the spur were not counted. The number
passing L2 was therefore counted on **slit-scan images** (`scripts/make_slitscan.py`):
the 3-px column at the line from every frame, side by side, so that each crossing piece
leaves one streak, independent of any detector. Unclear streaks were checked on the
video frames.

* **Procedure check at L1, where the true count is N:** 10/10, 49.5/50 and 80/80
  (140 pieces, RMS relative error 0.6 %).
* **Reference at L2:** 672 pieces in 16 runs. Six streaks were first marked uncertain;
  on the author's check five were confirmed and one was rejected, so no uncertain
  pieces remain (the rejected point stays in `results/slitscan_points.csv` with
  certainty `rejected` and is not counted). The blind first pass, with these decisions,
  gives 669. Three pieces were added after the comparison with the detector crossings,
  each confirmed on the video.
* **Trapping efficiency of the spur, R = 1 − N_L2/N:** 0.49 pooled over the
  independent runs (mean 0.48 ± 0.06). Q40 gives 0.49 and Q60 gives 0.46 (Mann–Whitney

* **Reflections on the glass side walls.** Matching every detector crossing to a
  visually counted piece (`scripts/match_L2_crossings.py`) shows that pieces floating
  along a wall are also detected as their reflection in the glass and are counted
  twice. This accounts for 11 of the 30 extra RF-DETR crossings and 7 of the 13 extra
  YOLO11m crossings over all runs. The matching gates pairs by distance before the
  assignment, so a far pair cannot displace near ones.
* **Water-surface ROI.** A region of interest removes these reflections. It keeps box
  centres between the bed-wall junction lines of the calibration, widened by
  1.5 % of the bed width on each side (k + U(k), not tuned on the counts). This lowers
  the L2 error of every retrained detector and leaves L1 unchanged or slightly better.
  Margins of 0.75–3 % give the same counts; a margin of 0 removes real pieces at the
  walls.
* **Event-level agreement with ROI (all 16 runs):**

  | Detector | Recall | Precision |
  | --- | --- | --- |
  | RF-DETR (original) | 99.0 % | 97.2 % |
  | RF-DETR (retrained) | 98.7 % | 98.2 % |
  | YOLO11m | 97.6 % | 99.1 % |

  Misses (merged parallel sticks in dense groups) and extra counts (track fragmentation)
  partly cancel in the count. A count error is therefore a lower bound on the event
  error.
* **RF-DETR vs YOLO11m at L2.** RF-DETR counts slightly too many at L2; YOLO11m does
  not. Original RF-DETR vs YOLO11m gives p = 0.02 uncorrected (Wilcoxon), which is not
  significant after Holm correction over the 28 pairs. Retrained RF-DETR vs YOLO11m
  gives p = 0.35.

## Measurement problem

Wooden dowels are released upstream of a permeable spur dike in a laboratory flume and
filmed from above (3840 × 2160 px, 119.88 fps). Two vertical virtual lines are placed at
20 % (L1, inlet) and 80 % (L2, outlet) of the frame width. The measurand is the number of
pieces crossing L1 during a run; N, the number of pieces counted and released by hand,
is the reference value. L2 counts give the trapping efficiency R = 1 − N_L2 / N_L1.

The 16 validation runs are named `{N}{Q}` (for example `1040`: N = 10 pieces, discharge
code 40). All detector training images are frames 0–1998 of run `20040`
(`results/training_source.json`), so the other 15 runs are independent of the detector
training data and are used for the primary accuracy statistics.

## Pipeline

1. **Detection** (`scripts/extract_detections.py`, GPU, once per video and model): every
   frame is processed at a low confidence threshold (0.05) and all boxes and scores are
   stored. Filtering this output at any threshold t ≥ 0.05 gives exactly the detector
   output at t, so the operating threshold can be studied without re-running the GPU step.
2. **Tracking and counting** (`trackwood/pipeline.py`, CPU): confidence filtering,
   optional class-agnostic non-maximum suppression (NMS), a Kalman/IoU tracker and line
   counting. The tracker reproduces the original implementation (`legacy/`) operation for
   operation.
3. **Statistics** (`scripts/summarize_counting.py`, `trackwood/stats.py`): bias, mean
   absolute (percentage) error, Bland–Altman limits of agreement, Lin's concordance,
   bootstrap confidence intervals, leave-one-run-out calibration, paired Wilcoxon tests,
   one-at-a-time sensitivity and a GUM uncertainty budget.

### Corrections to the original counting code

* **Dead zone at the counting line.** The original rule assigned side 0 to a track
  centre within 1 px of the line and required the product of the sides of two
  consecutive centres to be negative. A track whose centre landed on the line was never
  counted; at about 3.7 px of motion per frame this lost 28–43 % of the crossings. The
  corrected rule skips points on the line and counts a change of the last non-zero side.
  Both rules are computed in every run (`legacy` and `fixed` fields).
* **Duplicate tracks with RF-DETR.** RF-DETR output was used without NMS, so one piece
  could produce two parallel tracks. Class-agnostic NMS (IoU 0.6, the value already used
  by the YOLO pipeline) is applied to both detectors in the nominal configuration.

## Reproducing the results

```bash
pip install -r requirements.txt
cp configs/paths.example.json configs/paths.local.json   # then edit the paths
python scripts/identify_training_source.py               # which run the training images come from
python scripts/prepare_datasets.py                       # random and blocked detector splits
python scripts/train_yolo.py --model yolo11m --split random
python scripts/train_rfdetr.py --split blocked
python scripts/extract_detections.py --detector rfdetr_base_legacy
python scripts/run_counting.py --detectors rfdetr_base_legacy yolo11n_legacy --grid nominal
python scripts/run_counting.py --detectors rfdetr_base_legacy yolo11n_legacy --grid sensitivity
python scripts/summarize_counting.py --detectors rfdetr_base_legacy yolo11n_legacy
# L2 reference and validation
python scripts/make_slitscan.py                          # slit-scan images of L1 and L2
python scripts/make_slitscan_bands.py 5040 L2 1060 1480 --chunk 220 --scale 2.5   # enlarged views for counting
python scripts/mark_slitscan_counts.py                   # marks results/slitscan_points.csv, totals
python scripts/run_counting.py --detectors rfdetr_base_legacy yolo11m_random --grid nominal_roi
python scripts/match_L2_crossings.py --detectors rfdetr_base_legacy yolo11m_random
python scripts/validate_L2.py
```

Detector definitions are in `configs/detectors.json`; tracking and counting
configurations in `configs/grids.json`.

## Data

The experiment videos (about 2.2 GB for the 16 validation runs) and the retrained model
weights are not stored in this repository; they will be deposited in a public data
repository with a DOI. The sample run `1az214` and the original YOLO weights
(`best400.pt`) remain available through Git LFS. Small derived tables are versioned in
`results/`.
